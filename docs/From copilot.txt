## 🚀 **Why Graph IR + Autodiff is ~11.8× Faster**

### 1. **Hash-Consing (CSE - Common Subexpression Elimination)**

When you write: `(relu (matmul x w) (matmul x w))` — PyTorch computes matmul **twice**.

Rusty's hash-consing builds `matmul x w` **once** and reuses it:

```lisp
; Pseudo-code:
(define g (graph-grad 
  (lambda (x w b t)
    (/ (tensor-sum 
         (tensor-mul 
           (tensor-sub (relu (tensor-add (matmul x w) b)) t)
           (tensor-sub (relu (tensor-add (matmul x w) b)) t)))
       4))
  X W B T))
```

Look at the code: `(matmul x w)` and `(relu (tensor-add (matmul x w) b))` appear in **both the numerator and denominator**. With CSE:
- **PyTorch**: computes each part separately, stores results, recomputes in backward
- **Rusty**: computes once in forward, **gradient rules reuse the same node** in the backward graph

### 2. **Graph Optimization (fold + DCE)**

**Constant folding** eliminates dead code at graph build time:

```lisp
; Before:
(* 2.0 (/ x (+ 1.0 1.0)))

; After folding:
(* 2.0 (/ x 2.0))
```

**Dead-code elimination (mark-and-sweep)** removes unused intermediate nodes (interp.rs lines 241-260, graph_ir.rs):

```rust
fn dce_nodes(nodes: &[Node], outputs: &[usize]) -> (Vec<Node>, Vec<usize>) {
    // Only keep nodes reachable from outputs
    let mut reachable = vec![false; nodes.len()];
    let mut stack: Vec<usize> = outputs.to_vec();
    while let Some(i) = stack.pop() {
        if reachable[i] { continue; }
        reachable[i] = true;
        for &a in &nodes[i].args { stack.push(a); }
    }
    // ... remap indices ...
}
```

This is **automatic** — no manual pruning needed.

### 3. **Reverse-Mode Autodiff is Efficient**

PyTorch traces execution; Rusty builds a **static DAG** beforehand:

| Aspect | PyTorch | Rusty Graph IR |
|--------|---------|----------------|
| **Build** | JIT tracing (traces actual execution) | Static AST → DAG (no execution) |
| **Backward** | Dynamic tape replay | One reverse sweep over the DAG |
| **CSE** | Not available (can't fuse across traces) | **Built-in** via hash-consing |
| **Memory** | Stores intermediate activations during forward | Forward nodes are **reused** in backward gradient rules |

Example from graph_ir.rs (lines 377-384):

```rust
(Op::MatMul, &[a, b]) => {
    // dL/da = g · bᵀ ; dL/db = aᵀ · g
    let bt = ib.intern(Op::Transpose, vec![b]);
    let da = ib.intern(Op::MatMul, vec![g, bt]);
    accum(&mut ib, &mut adj, a, da);
    // ...
}
```

If `b` is already in the graph (from forward pass), transposing it in the gradient **doesn't re-compute b** — it's shared.

### 4. **Smaller, Specialised IR**

Rusty's Graph IR only supports:
- Scalars & tensors
- Elementwise ops (±×÷)
- matmul, transpose, relu, sum, if

PyTorch handles **everything** (conv, normalization, attention, ...), so it has overhead for dispatch, shape inference, and generic backends.

## ⚡ **Fused Kernels — What's Missing**

### The Problem: Interpreter Loop

Even with CSE, you still have this bottleneck (lines 519-591):

```rust
fn eval_nodes(graph: &Graph, inputs: &[GVal]) -> Result<Vec<GVal>, String> {
    let mut vals: Vec<GVal> = Vec::with_capacity(graph.nodes.len());
    for node in &graph.nodes {  // ← walk every node
        let a = node.args.first().map(|&x| &vals[x]);
        let b = node.args.get(1).map(|&x| &vals[x]);
        let v = match &node.op {
            Op::MatMul    => t_matmul(a.unwrap(), b.unwrap())?,
            Op::Transpose => t_transpose(a.unwrap())?,
            Op::TAdd => t_binop(a.unwrap(), b.unwrap(), "tensor-add", |x, y| x + y)?,
            // ... for every node ...
        };
        vals.push(v);
    }
    Ok(vals)
}
```

**For each node**, you:
1. Look up arguments in `vals` (cache miss)
2. Branch on `node.op`
3. Call the operation (allocate new `Rc<Vec<f64>>`)
4. Push to `vals`

**With 100+ nodes in a graph, this is expensive.**

### The Solution: Fused Kernels

A **fused kernel** combines adjacent operations into one:

```rust
// Before (3 separate nodes + branches):
y = relu(x)           // Op::Relu
z = matmul(y, w)      // Op::MatMul
s = tensor-sum(z)     // Op::TSum

// After (fused into one kernel):
s = sum(matmul(relu(x), w))  // one call, no intermediate allocations
```

## 🔨 **How to Implement Fused Kernels**

### Step 1: Identify Fusion Patterns

Create a **fusion analyzer** that finds chains like:

```rust
// In graph_ir.rs, add after optimize_outputs:

pub struct FusionPattern {
    nodes: Vec<usize>,           // node indices in order
    pattern: FusionType,
}

pub enum FusionType {
    ReluMatmulTsum,              // relu(x) -> matmul(_, w) -> tensor-sum
    MatmulAdd,                   // matmul(a, b) -> tensor-add(_, c)
    TransposeMatmul,             // transpose(x) -> matmul(_, w)
    ScalarMultAdd,               // scalar * x + y
}

pub fn analyze_fusions(graph: &Graph) -> Vec<FusionPattern> {
    let mut fusions = Vec::new();
    // For each node, check if it starts a fusible chain
    for i in 0..graph.nodes.len() {
        if let Some(pat) = try_fuse_from(graph, i) {
            fusions.push(pat);
        }
    }
    fusions
}

fn try_fuse_from(graph: &Graph, start: usize) -> Option<FusionPattern> {
    let node = &graph.nodes[start];
    match node.op {
        Op::Relu => {
            // relu(x) followed by matmul(relu, w)?
            let uses = find_uses(graph, start);
            if uses.len() == 1 {
                let next = uses[0];
                if matches!(graph.nodes[next].op, Op::MatMul) {
                    // Check if matmul output feeds into tensor-sum
                    let matmul_uses = find_uses(graph, next);
                    if matmul_uses.len() == 1 && 
                       matches!(graph.nodes[matmul_uses[0]].op, Op::TSum) {
                        return Some(FusionPattern {
                            nodes: vec![start, next, matmul_uses[0]],
                            pattern: FusionType::ReluMatmulTsum,
                        });
                    }
                }
            }
        }
        _ => {}
    }
    None
}

fn find_uses(graph: &Graph, node_idx: usize) -> Vec<usize> {
    graph.nodes.iter()
        .enumerate()
        .filter(|(_, n)| n.args.contains(&node_idx))
        .map(|(i, _)| i)
        .collect()
}
```

fn eval_fused_kernel(
    graph: &Graph, 
    vals: &[GVal],
    fusion: &FusionPattern, 
    inputs: &[GVal]
) -> Result<GVal, String> {
    match fusion.pattern {
        FusionType::ReluMatmulTsum => {
            // Fused: relu(x) -> matmul(_, w) -> sum
            // (1) Get relu input
            let relu_node = &graph.nodes[fusion.nodes[0]];
            let x_idx = relu_node.args[0];
            let x = &vals[x_idx];
            
            // (2) Relu
            let relu_x = match x {
                GVal::Num(n) => GVal::Num(n.max(0.0)),
                GVal::Tensor { data, shape } => GVal::Tensor {
                    data: Rc::new(data.iter().map(|v| v.max(0.0)).collect()),
                    shape: shape.clone(),
                },
            };
            
            // (3) Get matmul's other arg
            let matmul_node = &graph.nodes[fusion.nodes[1]];
            let w_idx = matmul_node.args[1];  // assumes relu_x is args[0]
            let w = &vals[w_idx];
            
            // (4) Fused matmul without temp allocation
            let matmul_result = t_matmul(&relu_x, w)?;
            
            // (5) Sum directly (no temp tensor)
            match matmul_result {
                GVal::Tensor { data, .. } => Ok(GVal::Num(data.iter().sum())),
                GVal::Num(n) => Ok(GVal::Num(n)),
            }
        }
        FusionType::MatmulAdd => {
            // matmul(a, b) -> tensor-add(_, c)
            let matmul_node = &graph.nodes[fusion.nodes[0]];
            let a = &vals[matmul_node.args[0]];
            let b = &vals[matmul_node.args[1]];
            let matmul_result = t_matmul(a, b)?;
            
            let add_node = &graph.nodes[fusion.nodes[1]];
            let c_idx = add_node.args.iter()
                .find(|&&idx| idx != fusion.nodes[0])
                .copied()
                .unwrap();
            let c = &vals[c_idx];
            
            t_binop(&matmul_result, c, "tensor-add", |x, y| x + y)
        }
        _ => Err("Unsupported fusion pattern".into()),
    }
}
